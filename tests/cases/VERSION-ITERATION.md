# 版本迭代与数据库双路径冒烟

关联 [ADR-019](../../docs/decisions/ADR-019-version-inheritance.md)、[Azure 迁移](../../docs/AZURE-PERSISTENCE.md)。

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| VI-01 继承 | v1 生成可点击计数器；在同项目提出“标题改蓝色”并确认计划 | v2 计划列出新增与沿用；源码只改 `src/app.css`，原 `App.tsx` 字节相同；v2 manifest 保有完整规格；v1 仍可打开 |
| VI-02 明确删除 | 在 v2 要求删除 v1 功能 | 计划卡明确列出被删功能；未确认不得生成；没有明确删除时旧功能默认沿用 |
| VI-03 指针变动 | v2 运行期间将当前版本切到另一可用版本，然后尝试提交 v2 | 提交冲突；旧版指针和两个既有快照保持不变 |
| VI-04 回归 | 对 v1 既有操作和 v2 新操作做浏览器交互，刷新同项目预览 | 两套功能均可用；业务数据按当前 origin 恢复；构建和静态探针不能替代此用例 |
| PG-02 schema 升级 | 在 PostgreSQL v1 数据库中留项目、版本、事件，再执行迁移至 v2 并重启主 API/独立异常后台 | 原 ID、序号、指针和异常只读视图可查；新 run 能固定基线；重复迁移不改旧记录 |

本地用 SQLite 跑 VI-01/02/03；真实 PostgreSQL 在临时数据库跑 PG-02 和同一条 VI-01；Azure 测试域另按 [部署 TC](DEPLOYMENT-AZURE.md) 验证。未执行真实浏览器/数据库时不得记为通过。
