# 独立异常后台验收用例

依据：[异常收集实施契约](../../docs/EXCEPTION-OBSERVABILITY.md)、[ADR-003](../../docs/decisions/ADR-003-exception-console.md)、[PRD](../../docs/PRD.md)。过程结果与脱敏证据写入 `D:\AI\ATOM笔试\docs\EXCEPTION-VERIFICATION.md`。自动化使用固定假模型、临时 SQLite 与独立进程；不调用付费模型。

| ID | 步骤 | 通过标准 |
| --- | --- | --- |
| EX-01 模型失败 | 在隔离 run 注入 `ModelOutputError`，观察 run 终态、异常表和独立后台。 | 恰有一条 `model_output_invalid`；`trace_id` 与 run 一致；原因是安全映射文案，不含模型原文、prompt 或异常消息。 |
| EX-02 构建失败 | 让固定构建连续失败后成功或停机，按 Trace 查看异常中心。 | 每次失败有唯一 `build_check_failed` 警示及轮次、耗时、错误码/指纹等安全打点；最终停机另有终态错误，通过的检查只留打点；旧成功版本仍可用。 |
| EX-14 历史修复与安全边界 | 查询 Trace `93358163-746c-4ebd-9b63-cdc39c4499bf` 的旧构建记录；隔离 run 注入 CodeLoop 非法 JSON 并从已有构建候选恢复。 | 历史 3 次失败构建可见，缺失的当时用量/目标文件明示未知；拥有者能打开人工修复卡，未提交前不调用模型；运维 API 不含模型响应、生成源码、原始构建日志。 |
| EX-03 API 500 | 在隔离主 API 触发受控未处理错误。 | 响应为通用 500 与 `X-Trace-ID`；后台可按该 ID 查到 `api_unhandled`；不泄漏内部消息。普通 4xx 和取消不采集。 |
| EX-04 跨项目 | 用访客 A/B 各创建项目并触发失败，再以管理员密钥查询。 | 独立后台一次列出两项目；主应用原项目 API 仍按访客隔离；主应用无 `/api/ops` 或 `/ops` 管理入口。 |
| EX-05 权限 | 独立服务分别用正确、错误、缺失密钥，以及仅携带访客 cookie 请求列表/详情；另测未配置服务密钥。 | 正确密钥可读；其余为 401 或未配置 503，无记录内容和总数；详情不能靠异常 ID 绕过授权。 |
| EX-06 数据边界 | 在受控输入与异常文本放唯一敏感标记，检查 SQLite 异常表、运维 API 和页面。 | 标记均不存在；列表/详情只返回白名单字段；关联 run 只返回创建时间、Agent 执行秒数、调用数、Token 用量和计算出的存续时间；时间线仅 `type/at/seq`，不返回事件 payload。 |
| EX-07 独立部署 | 主服务停机、独立运维服务仍启动并连接同一 DB；使用只读连接尝试写业务表；检查 8000/8002 端口。 | 后台仍能查历史记录；只读写入失败；两个端口各自提供自己的应用，运维服务不调用主 API。 |
| EX-08 查询边界 | 插入超过两页、同时间戳且不同 ID 的记录；按项目/来源/错误码/Trace ID 过滤，翻页并更换过滤条件。 | 顺序稳定、无重漏；游标与筛选一致；非法 limit/cursor 为 422；任何查询最多返回 100 条。 |
| EX-09 页面状态 | 在真实浏览器依次验证未登录、正确/错误密钥、空库、筛选无结果、加载失败、详情、复制 Trace ID、刷新。 | 页面文案区分状态；错误不显示“0 条”；键盘可操作且复制有反馈；密钥不在 URL、存储或 bundle 中；刷新后需重新验证。 |
| EX-10 写入降级 | 让主服务异常记录写入失败，但保留原 run/API 状态处理。 | 原失败语义不被采集故障覆盖，不产生递归 500；服务端仅输出最小告警且不含敏感原文。 |
| EX-11 预算定位 | 构造执行时长超限终态，再读取历史泛化预算记录和新预算记录；在独立后台按 Trace ID 查看详情。 | 新记录指出 Agent 执行累计值与上限；存续时间另标“含用户等待”；历史执行值显示未知，不拿创建至异常时间充当执行预算；页面明确区分历史信息缺失。 |
| EX-12 源码边界 | 固定假模型连续返回 3 个同样违反生成边界的候选；另用 JSX 说明文字提及 `localStorage`。 | 第 3 次相同错误集合自动暂停，检查点保留受控反馈与目标文件；后台按 Trace ID 仅见一条 `unsafe_source` 与安全原因；无构建事件、无新版本；人工明确继续一次可从检查点恢复；说明文字不被误判为直接存储访问，实际访问仍被阻止。 |
| EX-13 计划校验 | 让固定假模型连续产出缺少刷新读回验收的计划，检查工作台结果卡、run 终态、独立后台。 | 两次校验后记录 `plan_validation_failed`；访客与管理员均看见同一项受控具体原因，工作台标题为“生成计划失败”，不显示构建检查；不归为 `agent_unhandled`，不保存模型原始计划，也不进入代码生成。未知子原因码只显示通用文案。 |

验收分层：后端自动化覆盖 EX-01–08、10；真实浏览器覆盖 EX-07 与 EX-09；跨机器统一数据库、正式管理员身份、HTTPS/限流/轮换需在上线环境实测，未实测记为未验证。独立运维后台可作为本地演示功能交付，但不能凭本地共享 SQLite 宣称已可跨机器部署。
