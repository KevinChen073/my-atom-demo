# MVP2 验收用例（v0.1）

依据：[PRD](../../docs/PRD.md)、[架构](../../docs/ARCHITECTURE.md)、[仓库约束](../../AGENTS.md)、[MVP1 用例](MVP1.md)。本清单检验 **SSE 事件恢复 + 隔离交互预览 + 生成应用的服务端数据持久化**，属于 ADR-004 之前的历史口径。MYATOM 建造工作台只验收桌面浏览器；生成应用是否适配手机按它自己的批准计划验收。

**版本标记**：本清单的数据接口用例是此前 MVP2 实施的历史验收口径，已被生成交付物的 [ADR-004](../../docs/decisions/ADR-004-generated-deliverable-boundaries.md) 替代，不得用于宣称最新 `localStorage`、5 版回滚目标通过。新边界的验收点见 [PRD §7](../../docs/PRD.md#7-测试与-tc-维护)；实现变更时须同步重写本清单并实测。

## 前置环境与记录格式

- 使用隔离测试数据库与产物目录；准备访客身份 A、B 和各自项目。固定假模型用于故障注入与自动化，真实模型只用于最终端到端验收。真实模型用例不得由假响应代替。
- 测试需求：“生成一个待办事项应用：新增任务、显示列表、标记完成、筛选未完成、删除任务；刷新后保留数据”。在计划卡明确实体、字段、受控 CRUD、验收点；若模型未计划持久化，退回修改后再批准。
- 记录环境/URL、代码工作树或提交、模型与模板版本、Runner/Preview 适配器、`project_id/run_id/version_id/trace_id`、事件游标、操作步骤、预期、实际、脱敏日志或截图。过程证据写在 `D:\AI\ATOM笔试\docs\MVP2-VERIFICATION.md`；TC 与自动化留在代码仓库。
- API 路径按架构的语义写；实现允许经适配器映射，但必须在证据中写明真实路由。浏览器检查要看生成应用中的真实状态及刷新后的服务端读回，不能只看工作台构建成功或静态截图。
- 若本地使用同宿主 fallback，仅可在可信本机执行；它不是可公开运行任意生成代码的安全沙箱。公网验收前必须有可信隔离 Runner 与独立预览 origin，或明确阻塞最终交付。

## P0：事件顺序、断线和恢复

| ID | 可执行步骤 | 预期 / 判定 |
| --- | --- | --- |
| TC-M2-SSE-01 顺序和回放 | A 发起 run，记录 `GET /api/runs/{id}/events` 全量事件；在澄清、计划、构建阶段各连接一次 `GET /api/runs/{id}/stream?after_seq=n`；随后断开并以最后已确认的 `seq` 重连。 | 每个业务事件有稳定 `event_id`、`run_id`、`schema_version`、时间与单调 `seq`；同一 run 的 `seq` 无重复/倒序。重连先给出 `seq>n` 的缺失事件，再接实时事件；前端按 `seq` 去重，最终活动流与回放 API 一致。 |
| TC-M2-SSE-02 网络断开 | 浏览器打开项目并运行到建造阶段；将 SSE 连接断开/临时断网，期间让服务端继续产生至少 2 个事件；恢复网络。 | 页面显示连接状态，按退避重连并补齐缺失事件；卡片/版本以服务端状态为准，不再次提交 run/确认/构建。刷新后游标恢复；若 SSE 不可用，轮询回放可继续。 |
| TC-M2-SSE-03 心跳与无活动 | 在等待计划态保持 SSE 连接至少两个心跳周期，期间不提交决策；再提交决策。 | 心跳约按配置（架构初值 15 秒）出现且不计入业务 `seq`，连接不因空闲中断；决策事件只显示一次。若服务端关闭连接，客户端能退避重连。 |
| TC-M2-SSE-04 授权与游标边界 | B 用自己的访客身份请求 A 的 stream/events；A 用 `after_seq=0`、末尾 `seq`、超大值、负值和非法值请求。 | B 不能读取 A 事件；A 的游标行为明确、无重复/全表泄漏或服务端异常。负/非法参数有安全处理；事件 payload 不含密钥或业务私有记录。 |
| TC-M2-SSE-05 服务重启 | 记录 run 的 `seq`，重启 API/worker，重新打开同一项目并连接 stream。 | run 与持久事件可恢复；重启前后 `seq` 连续，已批准计划和最后成功版本不丢；不会因恢复启动重复模型调用或生成第二个版本。 |

## P0：预览发布、隔离与失败

| ID | 可执行步骤 | 预期 / 判定 |
| --- | --- | --- |
| TC-M2-PREVIEW-01 真实交互 | 完成待办应用生成与构建，取得 `GET /api/versions/{id}/preview` 结果，在工作台打开预览；新增一条待办、标记完成、筛选。 | 预览加载的是该版本真实构建产物，按钮/输入/列表实际响应，结果与批准计划一致；工作台显示预览版本与状态，不用静态图片或假 iframe。 |
| TC-M2-PREVIEW-02 origin 和凭证 | 检查工作台与预览 URL 的 origin、iframe sandbox/CSP/代理头；在受控测试代码中尝试读取主应用 Cookie、`MODEL_API_KEY`、父页面 DOM/管理 API、宿主文件及其他项目数据。 | 预览是独立 origin 或等效隔离边界；只拿短期且限项目/版本的数据权限，不能读取主应用凭证、父页面状态、服务端密钥/文件或其他项目。若此项无法证明，禁止公网交互预览。 |
| TC-M2-PREVIEW-03 版本绑定与旧好版本 | A 先有 v1 成功预览，再提交新需求使 v2 构建/预览失败；从版本列表打开 v1，并重启服务后再打开。 | v1 的源码 hash、预览入口和已有业务数据保持可用；失败运行显示实际原因/测试卡，不冒充 v2 成功，不覆盖最后好版本。代码回退不自动回退业务数据。 |
| TC-M2-PREVIEW-04 无 Runner/预览过期 | 故障注入 Runner 不可用、预览 URL 过期/停止、构建成功但预览发布失败。 | UI 标明失败与可重试动作；构建产物和日志仍可查看；不会提供可点击的假预览。重试遵循幂等键，不重复版本。 |
| TC-M2-PREVIEW-05 不可信产物边界 | 让模型/测试夹具尝试在生成源码或 manifest 中加入额外脚本、外部 URL、任意依赖、路径穿越/读 `.env`。 | 服务端源文件、schema 和路径校验拒绝越权；Runner 限额/网络/执行身份符合环境选型。仅前端 iframe 属性不算通过沙箱安全验收。 |

## P0：生成应用业务数据

| ID | 可执行步骤 | 预期 / 判定 |
| --- | --- | --- |
| TC-M2-DATA-01 完整 CRUD 与刷新 | 在 v1 预览内新增待办“验收任务 A”，读列表，标记完成，筛选，再删除另一条；刷新预览、关闭重开、刷新工作台项目链接。 | 每一步真实请求受控数据服务；刷新/重进后已新增和更新的记录仍在、已删除记录不再出现。直接查询服务端持久存储与 UI 一致；浏览器 `localStorage/sessionStorage` 清空后仍可凭有效预览权限读回。 |
| TC-M2-DATA-02 跨项目和跨访客 | A/B 各生成待办应用，A 建一条带唯一标记的数据；B 用自己的凭证尝试 A 的 CRUD 路由、预览 URL/数据令牌，并用 A token 改写 project/version/entity 参数。 | B 无法读取/改写 A 数据；A token 只在授权项目/版本/schema 内生效；猜测 ID 不能代替授权；错误响应不泄漏私有记录。 |
| TC-M2-DATA-03 schema/字段和容量 | 依次提交 manifest 不存在的实体/字段、错误类型、超长值、无效方法、超量列表/写入。 | `AppDataService` 按已确认、版本化 schema 限制实体、方法、字段、类型和数据量；拒绝项不改变数据库；输入不会被当作 SQL/HTML 执行。 |
| TC-M2-DATA-04 版本语义 | 同项目 v1 写入数据后生成 v2；分别打开 v1/v2 预览，检查各自可见数据和 schema；如提供回退，执行后再查询。 | 数据命名空间/迁移规则明确且与计划卡一致；旧版本仍能读其兼容数据。代码版本切换不静默删除或回滚业务数据，迁移失败须显式报告。 |
| TC-M2-DATA-05 授权过期与重试 | 让预览专用令牌过期，尝试读写；重新取得有效预览入口后以相同 `Idempotency-Key` 和载荷重试写入，再用相同键提交不同载荷。 | 过期令牌被拒绝且不写入；相同键和载荷只创建一条并返回原记录；相同键不同载荷返回 409；前端提示重新打开/恢复，不静默丢数据。 |

## P0：评审端到端；P1：体验

| ID | 可执行步骤 | 预期 / 判定 |
| --- | --- | --- |
| TC-M2-E2E-01 评审主线 | 全新访客从项目创建→澄清→计划确认→真实模型生成源码→实际构建→预览新增/完成一条待办→刷新预览与工作台→重新进入项目。先本地后在公开 URL 复跑。 | 所有阶段、文件、构建日志、预览操作和业务数据是真实结果；刷新后项目、事件、版本、预览数据恢复。公开 URL 可由未登录评审独立走通，若需访客凭证须有清晰恢复方式。 |
| TC-M2-E2E-02 断线中的评审主线 | 在构建过程中切断 SSE，再恢复；继续到预览 CRUD。 | 不丢事件、不重复 run/版本，最终业务数据可刷新读回。 |
| TC-M2-FE-01 桌面预览状态 | 桌面宽视口依次观察空、加载、成功、预览失效、数据错误和旧版本状态；用键盘操作工作台与预览主要控件。 | 文案与服务端真状态一致；预览与活动流不互相遮挡；关键控件有可辨识名称与焦点；错误有重试/返回路径。 |
| TC-M2-FE-02 未知事件/卡片 | 注入未知 `type/schema_version`、乱序/重复事件和缺少非关键字段。 | 前端安全降级，原始项目状态仍可恢复；不执行返回的 HTML/脚本，不因单条事件丢失后续业务事件。 |

## 执行分层与退出判定

1. **自动化**：使用固定假模型与临时数据库/隔离 Runner；覆盖事件契约、授权、CRUD/schema、失败/旧版本、重启。不得调用付费模型，也不得依赖预置页面假响应来判定真实生成。
2. **真实桌面浏览器**：用本地或测试环境完成 `TC-M2-PREVIEW-01`、`TC-M2-DATA-01`、`TC-M2-SSE-02` 的实际 UI 旅程，检查网络与服务端数据；截图、日志脱敏归档到过程记录。
3. **真实模型与公开部署**：`TC-M2-E2E-01` 由真实模型与真实构建执行，并在公开 URL 复跑。若使用同宿主 fallback 或缺独立隔离，标记“本地功能通过，公网安全阻塞”，不能声明笔试最终交付。

MVP2 退出要求：所有 P0 用例通过且证据覆盖真实浏览器 CRUD 刷新、SSE 断线恢复、跨项目隔离、预览安全边界；任何无法实测项标为阻塞/未验证并保留具体原因。P1 缺陷可分级，但不得掩盖 P0 失败。测试结果必须区分固定假模型、真实模型和公开 URL 三种证据。
