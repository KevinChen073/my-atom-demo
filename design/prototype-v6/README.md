# MYATOM 设计原型 V6 · 待用户确认

本版是独立的桌面界面候选，使用静态 HTML、CSS、JavaScript 和浏览器本地存储模拟项目状态。它没有接入模型、代码生成、真实测试或发布服务。**只有用户确认本原型后，才可作为正式产品界面调整的依据。**

## 打开与评审顺序

在仓库根目录启动 `py -3 -m http.server 8765 --bind 127.0.0.1 --directory design`，打开 [V6 原型](http://127.0.0.1:8765/prototype-v6/)。V5 保留在相邻目录，供对比。

建议依次看新建项目页、每周支出记录的对话历史与预览、番茄钟待办的需求确认，再点击右侧“概览 / 文档 / 测试 / 发布”。

## 三个区域的职责

| 区域 | 固定内容 | 主要交互 |
| --- | --- | --- |
| 左侧，默认 220px | 所有项目、新建项目、搜索、历史项目 | 切换项目后进入目标项目的工作台；“所有项目”打开可搜索的项目选择层 |
| 中间，默认占剩余宽度约 56% | 按时间顺序排列的用户与 Agent 对话、当前决定或结果、输入区 | “查看历史”定位到最早消息，“回到当前”定位到当前决定或结果；项目内切换右侧视图时，对话阅读位置与草稿保持 |
| 右侧，默认占剩余宽度约 44% | **本区域顶部**的“工作台 / 项目概览 / 项目文档 / 测试 / 发布”及所选内容 | 导航固定在右侧顶部，点击只替换右侧内容；工作台内可在预览与代码之间切换 |

项目名称和状态位于两个内容区域共同的顶栏。右侧收起后，中间对话占满可用宽度；重新打开右侧即可继续切换右侧视图。右侧可临时放大。分隔线支持拖动、键盘方向键和双击复位，布局保存在当前浏览器。

## 新建项目与对话过程

首页只保留一个主要目标：输入想做的网页应用。输入框下方有三个基础样例卡，点击后**仅填入**需求，用户仍需点击“创建项目”。左侧历史项目提供找回入口。顶部“查看首次使用”可演示历史为空时的样子。

工作台示例用对话形式表达流程：用户提出需求 → Agent 提出一个会影响产品操作的问题 → 用户确认 → Agent 给出计划 → 用户确认 → Agent 给出结果。当前需要操作的卡片作为最新一条 Agent 消息出现。较技术性的过程记录默认折叠；模拟结果和真实能力边界在界面中标明。窗口高度较小时，输入区仍保留，当前决策卡自动定位到可阅读位置。

这版共六个主要页面：新建项目、项目工作台、项目概览、项目文档、测试、发布。后五个页面共用同一个中间对话区，只切换右侧。左侧历史项目和“所有项目”用于跨项目切换。

## 可验证的交互

1. 在新建页点击一个样例卡：需求进入输入框，项目尚未创建；点击“创建项目”后进入新项目工作台。
2. 在“每周支出记录”点击“查看历史”：看到最初的用户需求及后续 Agent / 用户轮次；点击“回到当前”回到结果卡。
3. 在对话输入区写草稿，再点击右侧“项目文档”或“测试”：中间内容和草稿保持，右侧切换。
4. 点击左侧另一历史项目：项目标题、对话与右侧内容一起切到目标项目；再次回来时，草稿从浏览器本地模拟数据恢复。
5. 进入待确认项目：先选择选项，确认按钮才可点击；右侧在版本完成前给出明确的预览空状态。

示例的确认、计划、构建、测试、文件和发布信息都是模拟。对话输入区“提交”只保留草稿，不调用 Agent；右侧账本表单仅写入本地模拟数据。测试页的“示意通过”不是真实执行证据，发布页没有公网地址。
