# MYATOM 设计 Harness

> 状态：**V7 已确认为当前设计原型**。适用范围：MYATOM 桌面建造工作台及其独立界面原型。此文件是今后设计评审与回归的检查准绳；统一入口见 [design.md](design.md)，设计值见 [token.json](token.json)。

确认记录（2026-10-31）：用户明确表示“V7版本可用，作为当前的设计原型”。因此 V7 不再标记为待验收候选；后续界面设计以 V7 为当前参照。此确认针对**设计原型**，不等于原型内模拟能力已在正式产品实现，也不自动修改与 PRD 冲突的验收案例。

## 1. 决策边界

- V7 是当前已确认的设计原型，可作为后续界面设计与实现的视觉、布局和交互参照。验收记录不代表本文件的每条回归用例已在正式产品通过。
- 已批准的 [PRD](../docs/PRD.md)、[架构](../docs/ARCHITECTURE.md)和 [ADR-002](../docs/decisions/ADR-002-change-control.md)仍约束正式产品。原型与基线冲突时，先记录差异、影响和方案；用户确认该冲突变更后才修改条款或据此实施。
- [V7 原型](prototype-v7/README.md)只模拟浏览器内状态。它展示对话、预览、文件、测试、发布的**界面形态**，不证明真实 Agent、生成、测试、预览网关或发布能力。
- 本次设计范围是桌面 MYATOM 建造工作台，目标视口为 1280×720、1366×768、1440×900。生成出来的应用是否适配手机，由各应用需求决定。

## 2. 用户反馈 → 可执行规则

| 来源与反馈 | 设计规则 | 验收观察 |
| --- | --- | --- |
| 初版偏离常见 AI Agent 产品，信息平铺、缺乏聚焦 | 保留常见的对话＋预览心智；首屏只突出当前任务与一个主动作，状态信息按需展开 | 5 秒内可找到当前项目、当前 Agent 阶段、下一步；无等权卡片墙 |
| 需要历史项目、对话和预览/文件共存 | 左侧是历史项目，中间是主要对话，右侧是预览或项目内容；三者不是等宽仪表盘 | 在工作台上能连续阅读对话，同时看到右侧对应结果 |
| 多项目需要明确 | 左侧可找历史项目；“所有项目”为独立弹层；切换项目后，标题、对话、右侧状态及 URL 一起切换到目标项目工作台 | 不出现 A 的内容配 B 的标题；返回旧项目可继续其状态与草稿 |
| 项目概览/文档/测试/发布只改变右侧 | “工作台 / 项目概览 / 项目文档 / 测试 / 发布”固定在右侧栏顶部；点击仅更换右侧内容 | 中间对话不重新挂载、不丢草稿与阅读位置；浏览器前进后退可用 |
| 首页参考 ChatGPT/Atoms，尽量简洁 | 首页以 H1、一个需求输入框为主体；输入框下恰好三个基础样例卡；选择样例只填草稿 | 需用户再次提交才创建项目；项目列表不挤占首页主视觉 |
| 需要验证“对话形式的 AI Agent” | 历史按“用户需求 → Agent 澄清 → 用户决定 → Agent 计划 → 用户确认 → Agent 结果”呈现；当前决策/结果接在时间线上 | 可识别双方轮次、因果和当前待办；过程记录可折叠 |
| UI 略简陋，有 AI 模板感 | 轻量 MYATOM VI：暖白底、深绿结构、陶土色决策；一套线性图标；区别用户消息、Agent 更新、待确认卡和结果；动效只解释状态变化 | 品牌、图标、控件一致；预览中的应用有独立边界，不复刻平台外壳 |
| 字体过小 | 使用 [token.json](token.json) 的 V7 字阶：辅助 14、元信息 15、标签 16、对话 17、正文 18px，标题 21–50px | 在三个桌面目标视口可读，关键按钮与待确认项无需缩放即可操作 |
| 去除无用字眼 | 移除“先说清目标，细节可以稍后补充”“此处为界面草稿，提交不会调用模型”等解释性赘字；保留对完成任务必要的状态与错误反馈 | 首屏无重复提示；原型仍通过统一标识说明模拟边界 |
| 首页奇怪图形与标题动效 | 去掉 H1 上方的菱形；标题依次打字、停顿、删除：“今天想做什么？”“快速产出产品模型？”“一个绝妙的主意！” | 动效不改变布局；减少动态效果时静态显示第一句，辅助技术读到稳定标题 |
| MYATOM 的 VI 是左上角图标 | 所有历史和当前 MYATOM Agent 回复使用同一 `brand-mark.svg`，30px 头像；空状态也不换用另一枚菱形 | 逐条检查 Agent 回复无混用图标；用户消息不误用 Agent 标记 |

长任务补充检查：当前进展须有真实阶段、已确认内容、下一步和服务端累计执行时间；计划任务只标拟做，构建/预览/入库只凭实际事件勾选。等待用户时计时停止，结束后结果优先、过程折叠。静态资源探针不能写成浏览器交互通过。依据 [ADR-012](../docs/decisions/ADR-012-user-facing-run-progress.md)，验收见[长任务进展 TC](../tests/cases/RUN-PROGRESS.md)。

## 3. 交互护栏

1. **先确认再生成。** 澄清、计划与构建失败卡负责呈现和采集，唯一对话提交入口是当前卡下方的“发送”；右侧状态页可链接“回到工作台”，不复制确认按钮。采用建议是选择答案，不是提交。计划只在收到明确、无修改和未决问题的批准时进入生成；技术过程默认收起，用户在读历史时不被自动拉回底部。见 [ADR-010](../docs/decisions/ADR-010-structured-card-single-send.md) 与 [ADR-011](../docs/decisions/ADR-011-decision-turn-composer.md)。
2. **预览讲事实。** 尚无可用版本时显示当前阶段与未就绪说明；真实版本、可交互预览、测试通过和公开链接都必须有对应的后端状态或证据。模拟原型必须持续可辨认。
3. **同项目换视图保留上下文。** 只替换右侧；当前对话、输入草稿、阅读位置、预览/代码选项按项目保留。切换项目时这些状态按项目隔离。浏览器后退/前进恢复 URL 对应视图。
4. **布局可调且可恢复。** 左侧与中间分隔线可拖动、可键盘操作；右侧可收起、放大及恢复默认。偏好存浏览器本机；改变宽度不能把主动作挤出可操作区域。
5. **键盘与动效。** 可见焦点、语义标签、`Esc` 关闭弹层并恢复焦点；状态不能只靠颜色。`prefers-reduced-motion` 下停止循环标题和空间过渡，功能与文字反馈保持完整。

## 4. 设计回归路径

| ID | 操作 | 通过条件 |
| --- | --- | --- |
| DH-01 | 打开 `/`，输入需求、点击三个样例卡之一 | 首屏聚焦输入；只有三个样例；点卡只填草稿；提交后才进入项目 |
| DH-02 | 在项目 A 读历史、卡上回答澄清、卡下发送修改和批准 | 对话能看懂用户原文、结构化答案与 Agent 解释；卡内无提交按钮；只有卡下“发送”执行对话提交 |
| DH-03 | 在项目 A 依次打开右侧五个视图并浏览器后退 | 只有右栏变更；对话、草稿、阅读位置不丢；URL 与高亮一致 |
| DH-04 | 用左侧历史或项目切换弹层进入 B，再返回 A | 三处项目身份一致，无数据闪混；草稿与局部选择按项目恢复 |
| DH-05 | 收起、放大、拖动、键盘调整两处分隔线，再恢复默认 | 对话与右侧可用；本机重开后布局偏好生效，重置可回默认 |
| DH-06 | 检查新建、澄清、计划、构建中、结果、空/加载/失败状态 | 无假预览、假测试或假发布；等待卡的对话提交只在卡下“发送”，其余状态有明确下一步 |
| DH-07 | 在 1280×720、1366×768、1440×900 检查首页与工作台 | 文字可读；当前卡片及操作可达；右侧导航在右栏内完整可用 |
| DH-08 | 启用减少动态效果并以键盘操作 | 标题静态、无闪烁光标；焦点清楚；弹层可退出；全部流程可达 |
| DH-09 | 逐条检查历史和当前 Agent 回复 | 均使用左上角同源品牌标记，无混用占位符或装饰菱形 |

这些是设计回归用例，不是本次已经执行的正式产品功能测试。每次修订原型，应记录所检查的视口、交互、结果及未覆盖项；正式产品落地时另建实现与回归记录。

## 5. 与正式产品仍待对齐的事项

1. **首页三个样例的题目**：[PRD §4](../docs/PRD.md)指定“番茄钟待办、点老头游戏、移动点单”，V7 原型使用“每周支出记录、番茄钟待办、周末行程”。V7 可按现状作为设计参照；替换正式产品样例及对应验收案例仍须单独确认。未确认前正式产品继续按 PRD。
2. **主题范围**：PRD 的 MVP4 包含默认与二次元主题；V7 只展示默认主题。原型获确认不代表双主题已完成或取消。
