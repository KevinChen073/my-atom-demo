# 设计侧决策记录：从结构示意到视觉定稿候选

日期：2026-10-31。范围：MYATOM 桌面建造工作台。来源：用户对[多项目页面设计](README.md)的反馈，认为交互逻辑正常，但 UI 稍显简陋，希望评估 VI、Icon、特效并降低“AI 感”。本记录只改变视觉表达，不更改六个主页面、项目切换路径或服务端状态契约。

## 本次确认的方向

1. **保留六页与两种切换行为。** 跨项目切换进入目标项目工作台并替换整套项目数据；同项目内只换右侧页面，中间对话保留。以 [交互说明](INTERACTIONS.md) 为准。
2. **升级为轻量产品 VI。** 定义一枚可缩放品牌标记、MYATOM 字标、色彩使用比例、标题/正文关系、项目标识规则与一条“从输入到版本”的细线/节点母题。VI 主要出现在全局入口和项目导航，不占用预览区域。
3. **建立一致的图标系统。** 工作台、概览、文档、测试、发布使用一套 20px 线性图标，保持笔画、端点和视觉重量一致；通用操作继续使用熟悉的符号和文字标签。项目列表的数字圆点改为有项目身份意义的标识。状态徽标使用图形加文字，不用孤立彩点。
4. **先修视觉层级和组件，再加动效。** 项目中心突出创建与继续；工作台突出实际预览；四个状态页分别呈现“阶段、文档、证据、发布条件”的任务结构。对话中的用户消息、Agent 更新、待确认卡和版本结果拥有不同但协调的样式。
5. **预览有独立的应用边界。** MYATOM 外壳保持“编辑台”风格；右侧生成应用可以有其自身配色。预览用清楚的工具栏、运行状态和容器边界区分，不把平台 VI 强加给用户生成的应用。
6. **动效是反馈层。** 项目切换、右侧换页、确认提交、预览就绪采用短促且可中断的过渡；不使用无限循环发光、假百分比、粒子背景或同时发生的多组动画。`prefers-reduced-motion` 下即刻切换，功能完整。

## 上一版问题与本版修改

| 上一版可见问题 | 本版修改 |
| --- | --- |
| 左上角方形 M、项目行数字圆点像占位符 | 设计开口框与节点品牌标记、正式字标及项目字标 |
| 五个导航项主要靠文字和孤立小圆点 | 配套线性图标、当前项窄强调线和文字状态；去掉无语义编号 |
| 六页共享近乎相同的浅色面板，主题识别弱 | 不改变布局，把页标题、状态摘要、内容组织做出任务差异 |
| 对话记录多为同形灰块 | 区分用户输入、已确认内容、真实版本结果与可执行动作 |
| 平台 UI 和预览中的生成应用使用同一套绿色 | 让预览拥有明确边框与独立应用视觉；平台外壳不侵入预览 |
| 动效只写时长，缺少触发/结束规则 | 补充事件、时长、被打断和减少动效状态，提供视觉分镜 |

## 实施优先顺序与验收

先完成 VI 与图标底座，再精修项目中心、工作台两张关键页；四个状态页继承同一体系，最后补齐微动效和空/加载/错误状态。V3 输出位于 [v3/](v3/README.md)。

验收时检查：5 秒能识别当前项目与下一步；能分清 MYATOM 外壳和生成应用；图标在 20px 尺寸仍可识别且有文字；项目切换不混淆数据；动效关闭后所有状态仍可理解；未执行测试与未发布状态不被画成成功。

参考的取舍依据：[Linear 的界面更新](https://linear.app/now/behind-the-latest-design-refresh)强调让任务主区获得权重、减少多余图标和边界；[Atlassian 图标原则](https://atlassian.design/guidelines/product/foundations/iconography)强调图标体系一致且辅助文字；[Atlassian 动效原则](https://atlassian.design/foundations/motion)将动效用于解释变化并尊重减少动态效果。这里是对这些原则的 MYATOM 设计推论，不复制相关产品界面。
