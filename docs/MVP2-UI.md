# MYATOM MVP2 桌面工作台界面（v0.1）

状态：2026-10-31，MVP2 实施设计。产品范围以 [PRD](PRD.md) 与 [架构](ARCHITECTURE.md) 为准，桌面布局遵循用户确认的 [工作台 v2](WORKBENCH-V2.md)，MVP1 卡片门禁延续 [MVP1 UI](MVP1-UI.md)。冲突按 [ADR-002](decisions/ADR-002-change-control.md) 处理。

**当前边界**：本页关于 `manifest.entities`、服务端数据 API 和旧版 schema 的描述是 MVP2 旧实施设计；生成交付物以 [ADR-004](decisions/ADR-004-generated-deliverable-boundaries.md) 为准。澄清/计划/修复等待态的提交位置与语义以 [ADR-010](decisions/ADR-010-structured-card-single-send.md) 为准。回滚指针、`localStorage` 提示与 5 版上限已实现；浏览器业务交互仍需实际验收。

## 1. 核心体验

工作台保留“对话与决策在中间、运行成果在右边”的阅读顺序。左侧是项目导航和最近项目。无可用版本时右侧默认收起，对话占满主区；计划形成后可手动打开项目文档。生成首个可用版本后右侧展示真实交互预览，“代码”页签可查看该版本源码；新一轮失败时仍可查看旧版。切换项目内容视图只更换右侧内容，中间对话、卡片草稿与滚动位置不卸载。没有有效预览时不使用静态模拟应用。

仅设计桌面浏览器，基准为 1440×900，并检查 1280×720 与 1366×768。顶部项目栏 64–70 px，左导航 192–216 px，预览就绪后中间对话 400–440 px，其余宽度给右侧，尽量保持预览可用宽度至少 620 px。尚未有版本时，中间决策区可扩到约 560 px。三块区域各自滚动，对话底部的“继续迭代”输入框不随事件列表滚走。

视觉延续暖中性底色、墨绿信息层级和陶土橙主动作；左导航改为比内容略深的**浅色**背景。状态附文字，不能只靠彩色圆点表达；正文 15–16 px，辅助文字 13–14 px。生成应用可以有自身视觉风格，预览容器不强行覆盖其 CSS。

## 2. 右侧导航与视图

| 入口 | 右侧内容 | 数据来源与空态 |
| --- | --- | --- |
| 工作台 | 预览/代码切换、版本选择、保存与预览状态 | 版本 manifest、预览 API；无版本显示“尚无生成版本” |
| 项目概览 | 项目目标、当前 run 状态、最近成功版本、下一步 | 项目/运行/版本快照；无 run 显示创建需求引导 |
| 项目文档 | 当前需求、计划及持久化实体字段 | `runs[].request_text`、`plan`、`approved_spec_version`；未批准明确标“待确认”，旧计划标出所属批准版本 |
| 测试 | 各构建命令结果、浏览器检查实际状态、日志入口 | `test_result` 卡与版本 manifest；未执行不能显示通过 |
| 发布 | 发布条件、当前状态、实际 URL 或阻塞原因 | MVP2 未有发布事实时显示“尚未发布”；不展示假链接 |

左侧导航应是按钮或链接，有可见当前项。切换后右侧标题获得键盘焦点；返回工作台恢复之前选中的版本、预览/代码页签和源码文件。活动中的澄清卡或计划卡仍在中间，右侧导航不改变后端阶段。

## 3. 实时进度与连接恢复

- 初次进入项目：先读服务端项目快照，再按当前 `run_id` 获取缺失事件；绝不因打开页面重新提交 run。接 `GET /api/runs/{id}/stream?after_seq=N` SSE，事件 `data` 是原事件记录、`id` 为 `seq`。
- 客户端用 `(run_id, seq)` 去重且按 `seq` 排序。每次连接或重连先用 `GET events?after_seq=N` 补历史，再接流；在流连接期间若收到重复事件仍只显示一次。服务端状态和卡片以项目快照为准，事件仅补活动记录。
- 15 秒心跳只表示连接存活，不追加活动项。连接状态明确区分“实时连接 / 正在恢复 / 已切换轮询 / 连接中断”；断开时指数退避与抖动重连，失败转有界轮询。恢复后校对 run 状态和卡片版本。
- 收到完成、失败、取消或预算终态事件时，关闭实时连接并补读一次快照与事件；刷新后处于终态的 run 不再建立 SSE，以免服务端正常结束流被误报为断线。
- 对话按用户需求、Agent 澄清、用户回答、Agent 计划、用户确认、阶段进展和结果组织；当前阶段只展示可理解的简短说明。原始模型事件、用量及命令日志不进入访客主时间线，构建证据留在测试视图按需查看。取消后等待服务端最终状态。旧的成功版本在新 run 失败或断线时仍可查看。

## 4. 预览、代码与业务数据状态

1. 用户选择版本时，保留版本选择；工作台“预览”页签调用 `GET /api/versions/{version_id}/preview`。成功响应 `{url, expires_at}` 后才挂载 iframe。忽略初始 `about:blank` 加载事件；实际页面超过 12 秒未载入时显示重试/切代码。过期、拒绝访问、运行失败分别给出原因。预览 URL 需与工作台不同 origin；不满足时拒绝挂载。
2. 预览 iframe 用 `sandbox="allow-scripts allow-forms allow-same-origin"`，不授予顶层导航、弹窗或主应用权限。本地预览来自每项目独立的 `http://p-<project_uuid>.localhost:8001`，主站来自 `http://127.0.0.1:8000`。工作台每次载入或点击“重新载入”都申请新的一次性票据；接口返回的 `expires_at` 是票据兑换期限，不能显示为已载入预览的失效时间。预览会话过期后提示重新载入。此隔离仅为本地测试边界，**不表示公网不可信代码执行已有安全沙箱**。
3. 版本 manifest 的 `preview.status = local` 只是“可尝试本地预览”；真正“预览就绪”取决于预览 API 成功及 iframe 加载。旧版本也可请求该 API，失败则显示原因，不静默切到最新版。
4. “代码”页签显示该版本文件树与只读源码；切换回预览不改变选中版本。长日志与代码在右侧独立滚动。
5. 声明 `manifest.entities` 的新版本可通过独立 origin 的受控 API 保存数据。主工作台提示“本版本声明了服务端数据结构；提交后刷新核对”。旧版本未声明实体时明确提示需核对其实际保存行为。除非预览协议提供可信写入/同步事件，主工作台不能声称“刚刚已保存”。预览内的具体提交结果由生成应用显示，刷新读回是验收证据。
6. 批准计划前和项目文档中，都结构化展示计划声明的 `entities[].name`、字段名、类型和必填标识。`data_model` 自然语言不能代替实际持久化 schema；旧版计划没有 `entities` 时只展示已有记录，不推断字段。

## 5. 失败与恢复文案

| 情况 | 用户可见状态 | 可执行动作 |
| --- | --- | --- |
| SSE 断开、HTTP 快照仍可用 | “实时连接中断，正在补齐活动；任务可能仍在运行” | 继续观察，必要时手动刷新 |
| 连续流失败，轮询成功 | “正在使用定时更新” | 重新连接实时流 |
| 流和轮询都失败 | “无法同步最新状态；上次同步于…” | 重新连接，不重复提交 run |
| 预览 API 404/403/过期 | “该版本预览暂不可用”加原因 | 重试预览、查看代码 |
| iframe 加载失败 | “预览页面未能载入” | 重试、切代码、查看测试 |
| 新 run 失败 | 显示失败测试卡与最后成功版本 | 查看旧版、改需求再试 |
| 旧版数据 schema 与当前版不同 | 显示该版本标识和数据隔离说明 | 在所选版本内验证，不声称回滚业务数据 |

构建日志显示前移除 ANSI 控制序列，只作为纯文本渲染。所有错误保留可操作下一步，绝不把连接中断写成构建失败。

## 6. MVP2 前端验收

测试用例与证据记录见 [MVP2 TC](../tests/cases/MVP2.md)。设计重点：1440×900、1366×768、1280×720 的三栏可读性；左导航切换后中间草稿与滚动不丢；预览/代码与版本状态保持；SSE 回放无丢失/重复；预览内完成业务数据新增、编辑、完成、删除并刷新读回；挂起 iframe 的 12 秒超时与重试/切代码；失败后旧版仍可预览；另一项目会话不能读取该版本。公开 URL 的能力仍需另做线上验证，不能用本地预览替代。
