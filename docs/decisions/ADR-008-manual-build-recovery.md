- 状态：Accepted（用户于 2026-11-01 明确要求）
- 关联：[PRD](../PRD.md)、[架构](../ARCHITECTURE.md)、[MVP1 交互](../MVP1-UI.md)、[ADR-006](ADR-006-single-main-run-scope.md)。

## 背景与决定

构建失败后直接结束 run 并只允许重开需求，会丢失已批准计划、候选源码和构建证据。人工处理前必须给出小结：失败命令、最近错误、逐次构建结果、已自动修复轮数、可核对的日志入口及基于证据的原因提示。小结不由模型猜测，不把失败候选算入可用版本。自动修复阈值及提前停机条件由 [ADR-009](ADR-009-build-repair-harness.md) 修订。

源码编译/类型错误进入 `WaitRepair`，暂停执行计时并等待项目拥有者明确选择：

1. **继续修复一次**：把最近诊断和已有计划交给受限 `CodeLoop`，只生成一轮候选，再构建；不重跑澄清与计划。
2. **指定修复方向**：用户输入 3–2000 字方向；它只能细化源码修复，不覆盖已批准需求、模板和 [ADR-004](ADR-004-generated-deliverable-boundaries.md) 的本地持久化边界。仍只生成一轮候选。
3. **用现有代码重新构建**：不调用模型、不改源码，只重新执行构建。适用于环境已恢复等有明确理由的情况；不自动触发。

依赖安装或环境故障不允许自动改代码，只提供用户主动的重新构建。按 [ADR-010](ADR-010-structured-card-single-send.md)，三个恢复动作通过底部单一“发送”解释，并经当前卡动作白名单校验；卡内只显示错误小结、证据和定位输入区控件。每次手动动作都有独立决策卡版本与幂等键；再次失败形成新小结、等待下一次选择。模型调用、token 和累计 Agent 执行时间继续使用同一 run 的硬预算，人工等待不计时。预算耗尽、取消、需求不完整和预览隔离失败仍为终态。

历史 `NeedsUser` 构建失败 run 若仍是该项目最近一次、保留了 LangGraph 构建检查点、批准计划仍符合当前模板且预算未耗尽，可由项目拥有者显式打开修复选项；不得在读取页面或服务重启时自动重跑。恢复动作重建等待节点，不重做旧副作用。若旧计划依赖已移除的 `appData` 等服务端业务存储，则展示冲突原因，只允许修改需求后新建 run，不能让修复悄悄改变批准计划。旧版继续可用；只有构建和预览检查通过才提交新快照。

此决定仅调整 [ADR-006](ADR-006-single-main-run-scope.md) 中“所有 `NeedsUser` 都结束当前 run”的构建失败部分，不引入复杂需求跨阶段回退或通用 CodeAgent 子图。
