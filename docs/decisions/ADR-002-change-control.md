# ADR-002：PRD 与架构变更守则

- 状态：Accepted（用户明确要求）；日期：2026-10-30
- 关联：[PRD](../PRD.md)、[架构](../ARCHITECTURE.md)、[AGENTS.md](../../AGENTS.md)

## 决定

任何后续需求变更、实施发现或平台 Spike 结果与现有 PRD/架构文档发生冲突时，**必须在修改冲突内容前向用户确认**。不能以“实现更方便”“平台可能支持”或“文档过时”为由擅自覆盖。

## 执行步骤

1. 定位冲突条款，记录当前基线、提出的变化及可验证证据。
2. 完成不依赖冲突决定的调查或原型工作，形成可评审的方案。
3. 向用户给出影响范围、选项、推荐方案和对 MVP/测试/迁移的影响，并明确请求确认。
4. 获得确认后更新 PRD、架构、Spike/TC 和交叉链接；重大决定增写新 ADR，旧 ADR 保留并标记被替代。
5. 未确认前维持原基线；可以记录“待决”，不可把未通过的 Spike 改写为已支持。

无冲突的细化（补充测试、修正文案、增加证据、实施已确认方案）可直接推进。用户在当前或后续会话明确授权的修改视为确认，不重复询问。此守则同时写入根目录 [AGENTS.md](../../AGENTS.md)。
