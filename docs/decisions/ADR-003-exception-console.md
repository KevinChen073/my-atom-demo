# ADR-003：独立部署的跨项目异常后台

- 状态：Accepted（2026-10-31 用户明确要求跨项目管理员后台，随后明确要求独立部署并仅通过统一数据库读取）
- 关联：[异常收集实施契约](../EXCEPTION-OBSERVABILITY.md)、[PRD](../PRD.md)、[架构](../ARCHITECTURE.md)、[变更守则](ADR-002-change-control.md)

## 决定

主应用仅向统一数据库写入安全异常记录。另建独立运维前端和服务端，由运维服务以只读数据库连接获取跨项目数据。主应用不增加 `/ops` 路由、管理员 API、管理员密钥或普通用户导航入口。运维服务独立启动和部署，使用自己的 `OPS_ADMIN_KEY` 校验管理员读取。异常记录沿用 run `trace_id`，原始异常消息、堆栈和业务内容不进入异常表。

## 理由与边界

现有产品只有项目访客身份，不能授予跨项目读取。独立部署隔离管理员入口与普通用户工作台。当前 SQLite 文件仅适用于两个本地进程共享同一磁盘；跨机器部署须先实测统一数据库服务/共享存储及只读权限。环境密钥是 Demo 级身份方案，公开部署前需要正式身份、HTTPS、限流、轮换和审计验证。此决策不宣称 Atoms Cloud 已支持该部署方式。

## 后续

主服务端、独立运维服务端与独立前端按[实施契约](../EXCEPTION-OBSERVABILITY.md)落地，并用隔离故障夹具验证记录、权限、脱敏和页面行为。若将来要合并部署或改变身份方案，按 ADR-002 先与用户确认。
