# ADR-005：对话优先与按阶段出现的成果区

- 状态：Accepted（用户于 2026-10-31 直接提出交互修订）
- 关联：[PRD](../PRD.md)、[架构](../ARCHITECTURE.md)、[MVP2 UI](../MVP2-UI.md)、[变更守则](ADR-002-change-control.md)

## 背景

V7 页面把“过程记录”、运行指标和无版本的右侧占位常驻展示。用户在澄清与计划阶段看到大量开发者信息和空成果区，当前决定反而被压缩。此决定修订 V7 的呈现方式，不改变 Agent 状态机或确认门禁。

## 决定

1. 主区按真实顺序呈现用户需求、Agent 澄清、用户回答、Agent 计划、用户确认、进展与结果。当前待决卡位于 Agent 消息内；已提交决策只读保留，刷新后从服务端记录恢复。
2. 访客主对话只显示当前可理解的进展与下一步。原始事件名、模型调用次数、Token、内部 run ID 不出现；构建证据在测试视图按需查看。失败时可按需显示 trace ID 供报障，跨项目异常仍由独立管理员后台处理。
3. 没有可用版本时右侧默认收起，对话占主区；计划形成后可手动查看文档。有可用版本时展示预览/代码，若新一轮尚未完成仍允许查看旧版。默认收起只影响空间分配，不伪造或删除服务端状态。
4. 底部保留同一个消息输入区。澄清卡出现时不自动切换成原需求编辑；点击“修改原需求”才进入可取消的全文编辑。补充需求与计划修改通过底部发送，卡片内不常驻重复文本框，未提交草稿仅在本浏览器会话保存。

## 验收

- 无版本的澄清、计划、运行和失败阶段，1280×720、1366×768、1440×900 下当前对话可读、确认动作可达，右侧默认不占宽度。
- 刷新后历史回答与计划决定仍按轮次出现；重复 SSE 事件不生成重复消息。
- 新一轮失败时旧版预览仍能打开；失败详情给出可定位的 trace ID，正常主界面没有模型用量与原始事件列表。

此 ADR 是用户本轮明确修订，按 [ADR-002](ADR-002-change-control.md) 无需重复请求确认；后续若再次改变这一边界，仍须先确认。
