# ADR-031：公开首页与邀请码测试空间

- 状态：Accepted（2026-11-02，用户选择方案 A）；公网入口尚未开放。
- 关联：[PRD](../PRD.md)、[架构](../ARCHITECTURE.md)、[ADR-020](ADR-020-azure-files-trusted-demo.md)、[ADR-026](ADR-026-shared-origin-project-storage.md)、[ADR-028](ADR-028-browser-model-key-both-environments.md)。过程记录在 `D:\AI\ATOM笔试\docs\MYATOM-PUBLIC-ACCESS-PROPOSAL-2026-11-02.md`。

## 决定

任意网络、任意人员可打开工作台首页；只有持有有效邀请码的测试人员可创建、生成、访问项目与预览。匿名访客即使提供自己的模型 Key，也不能创建项目或运行任务。测试人员可选用容器环境变量 `MODEL_API_KEY` 对应的平台测试额度，或填写自己的 Key。无需 loginId。高熵邀请码由用户私下发放，服务器只配置 SHA-256 摘要；同一码持有人共享项目、版本与额度，不同码对应不同空间。邀请码原文不进数据库、源码、日志或浏览器持久存储。签名会话 Cookie 使用 HttpOnly、Secure、SameSite=Strict；从配置中移除摘要后，旧会话不再有效。

平台模型 Key 只允许已验证邀请码绑定的 run 在额度内使用，不返回浏览器。每码每日模型调用与 Token 有服务端上限。用户自带 Key 仍按 ADR-028 存在浏览器 `localStorage`，因此同源预览脚本可读取它。

## 安全边界与取舍

沿用现有单容器 Runner 与同源预览，**不新增云端隔离 Job**。持码人员须是受信演示参与者，邀请码的发放范围由用户控制；持码者提交的需求及生成代码仍可能在拥有 SQL 与模型配置的主容器中构建，预览脚本也与工作台共享 origin。邀请码是访问门槛，**不是代码或浏览器隔离**。项目 ID 的 `localStorage` 前缀也不构成安全隔离。不能将此模式宣传为面向不可信公众的生成服务。若以后允许匿名 BYOK 生成或不受信人员持码生成，须按 ADR-002 另行确认隔离 Runner、预览 origin/存储桥与安全验收。

## 实施与验收

- Azure `azure_demo` 中，匿名仅可读取首页和空项目列表；所有项目、run、版本、预览和模型测试写入入口在服务端核验有效邀请码。登录失败有单副本内存限流；多副本需改共享限流。
- 创建 run 前再次核对平台 Key 配置及每码额度；运行时模型网关再验证邀请码摘要及 run 授权，撤销后不继续使用平台 Key。
- 开放入口前完成未登录/错码/伪造 Cookie/跨码/跨设备/退出/额度/预览的定向测试；部署后分别从允许 IP 外的网络打开首页、验证匿名受阻与持码主流程。Azure 环境的真实模型、构建和预览尚未完成验收。
- 此决定允许在上述受控范围内移除入口 IP 限制，但不改变 `APP_ENV=azure_demo` 的受信演示性质。实际 Azure 网络配置变更与上线结果须单独记录。
