# ADR-019：已保存版本的需求与源码继承

状态：已确认，2026-11-01。关联 [PRD §5](../PRD.md#5-持久化与版本)、[系统架构](../ARCHITECTURE.md)、[生成交付物边界 ADR-004](ADR-004-generated-deliverable-boundaries.md)、[变更守则 ADR-002](ADR-002-change-control.md)。

## 背景

旧流程每个新 run 只把本轮输入送进计划和 CodeLoop，导致 v2 可能把 v1 的功能当作不存在。用户确认按“固定基线、合并规格、从旧源码局部修改、复核旧能力”的方式优化。

## 决定

1. 已有版本的新 run 采用 `iterate` 模式；创建时在项目锁内固定当前 `active_version_id`，并保存该版本的完整已确认规格副本。无版本项目采用 `create`。已存在版本的项目不能用新建模式绕开继承；回滚后下一轮从回滚后的当前版本开始。
2. 计划节点在旧规格上添加本轮变化。旧功能、数据模型和验收点默认沿用；删除或替换功能须按旧条目原文列出，并在计划卡显式呈现，用户确认后才进入生成。新版本 manifest 保存完整有效规格，不依赖可能因五版上限被淘汰的祖先版本。
3. Prepare 从旧版本完整快照读取受控生成文件并核对 hash。CodeLoop 首轮优先重写计划指定文件，同时提供这些文件原文和未修改依赖接口；未定位文件时读取完整受控源码后重生。每轮候选仍按当前固定模板校验、构建、做静态预览探针。失败不提交版本、不改变当前指针；发布时再次核对当前指针仍是固定基线。
4. 计划沿用项、未修改文件 hash、构建和预览探针是自动门禁；它们不能替代旧功能的浏览器交互回归。TC 应覆盖 v1 核心流程与 v2 新增流程，未运行浏览器行为时结果标“未检查”。`localStorage` 数据仍按 ADR-004 不随代码快照回滚。

## 边界

此决策不增加跨 run 的通用意图路由、跨阶段 Agent 回退或通用 CodeAgent 子图。生成文件仍受最多 12 个、6 个组件、4 个 hook 和总量限制；累积计划最多 32 个功能、32 条数据模型、48 条验收点及 6 个页面，达到上限须明确要求缩小范围，不能静默截断旧要求。
