# ADR-034：业务数据保存说明与源码检查点

- 状态：Accepted；2026-11-03 用户要求生成需求说明并在校验时增加独立 Node。
- 关联：[PRD](../PRD.md)、[系统架构](../ARCHITECTURE.md)、[ADR-026](ADR-026-shared-origin-project-storage.md)、[变更守则](ADR-002-change-control.md)。

## 决定

`Plan` 输出 `business_data`：是否需要保存、保存哪些业务字段。服务端将存储位置、刷新读回验收和边界补齐到持久化计划中，工作台的“项目文档 → 需求”同步展示。用户可新增、编辑、删除或积累的业务记录应标为需要保存；纯静态内容和临时界面状态可标为无需保存。已批准的计划是检查依据，旧版迭代继承保存要求。

在 `ValidateSource` 之后、`BuildTest` 之前增加 `BusinessDataCheck`。若计划需要业务保存，该节点检查候选 TypeScript 源码中是否通过模板的 `generatedAppStorage.getItem` 与 `setItem` 读写。缺少任一项时记录问题、定位生成文件并回到 `CodeLoop`；复用现有自动修复轮次、重复错误停机和人工定向修复规则。静态页面按计划记录“不适用”。检查结果随版本 manifest 和测试结果卡保存。历史快照不追溯改写。

2026-11-03 线上移动点单版本出现 `order-demo:orders` 键名与模板规则冲突，应用将“数据键名无效”误报为“浏览器存储不可用”。模板现在允许冒号；`BusinessDataCheck` 对可确定的字面量及同文件常量键名核对模板规则，不合规时定向修复。动态拼接、跨文件引用和实际浏览器存储异常仍需运行时冒烟。已保存版本保持原快照，不会自动替换其中的模板文件。

这个 Node 的等级是 **`source_contract_only`**。它证明源码存在读写接线，不能证明用户点击后真正写入、刷新读回、数据格式兼容、容量足够或浏览器允许存储。`PreviewCheck` 仍只检查静态资源；测试页必须把浏览器交互列为未执行。真实业务保存需按需求文档的步骤做浏览器冒烟，记录成功或失败，不得把源码检查通过说成业务数据已保存。

## 验收

1. 保存要求为真而候选只有页面状态、只读或只写时，不能进入构建与版本提交；可定位文件时只重生该文件。
2. 同时具有适配器读写接线时进入构建，测试结果显示“源码通过”，浏览器检查仍显示未执行。
3. 需求文档列出保存字段、当前浏览器的 `localStorage` 范围、刷新读回及失败提示的验收动作，并说明清理存储、换浏览器和代码回滚的边界。
4. 无业务数据的静态页面可通过检查，旧版文档缺少新字段时展示待核对说明。
