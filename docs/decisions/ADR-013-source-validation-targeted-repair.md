# ADR-013：源码校验与定向文件修复

- 状态：Accepted（用户于 2026-11-01 确认）
- 关联：[PRD](../PRD.md)、[系统架构](../ARCHITECTURE.md)、[ADR-002](ADR-002-change-control.md)、[ADR-009](ADR-009-build-repair-harness.md)、[源码修复用例](../../tests/cases/MVP1.md)。

2026-11-02 补充：[ADR-029](ADR-029-generated-source-layout-relaxation.md) 取消 `App.tsx`/组件必须把状态放入 hook 及强制生成 `useAppState.ts` 的限制；本 ADR 的候选反馈、修复轮次和停机机制保持有效。

## 决定

当前 `CodeLoop` 不是任意工具规划的 ReAct Agent。一次调用生成一份候选文件映射；独立的确定性 `ValidateSource` 检查候选，再通过 LangGraph Edge 决定构建、重新生成或停止。首次模型输入包含与 Runner 一致的文件范围、大小、导入、状态与持久化限制。模型建议不代替服务端校验。

校验检查点只保存候选缓存引用、尝试编号、受控问题码、反馈和可修改文件路径，不把完整源码放进 LangGraph state。候选源码保存在本地受控 `node_outputs` 缓存中，缓存键按 run 和逐候选编号唯一；重放同一节点可复用同一结果。只有整份候选通过校验后才写入工作区、构建和保存版本。

反馈结构为 `origin`、`issues[{code,file,feedback}]`、`target_files`、`mode`。若所有问题都能定位到允许生成的具体文件，下一次 `CodeLoop` 仅收到原始需求、已批准计划/澄清事实和本轮反馈，仅返回这些文件的**完整内容**；其他文件由上一份候选保持原样。模型若额外返回其他文件，本轮拒绝，不能静默覆盖。若问题无法可靠定位、响应形状错误或缺少可恢复候选，则重新请求完整 `files` 映射。局部结果合并后仍对**整份候选**重新校验。构建诊断只有能定位到现有生成文件时才采取同样的局部修复；环境/依赖问题不改源码。

初次生成不计修复轮；源码校验和源码编译/类型失败共用最多 **60 轮自动修复**。最近 3 次完整错误签名集合相同、某具体错误累计第 5 次、预算/取消或明确不安全能力触发停机。源码校验停机也展示受控问题小结，允许用户在同一 run 内明确选择再修一次或指定方向；人工每次只执行一份候选，仍沿用原预算。没有通过源码校验的候选不执行构建、不占 5 个可用版本额度，也不改变旧版。

本决定扩展 [ADR-009](ADR-009-build-repair-harness.md) 原先仅对 `BuildTest → Diagnose → CodeLoop` 计数的规则：两类源码修复共用上限和停机历史。`CodeLoop` 仍是固定技术栈的单 Agent 节点，不引入通用 CodeAgent 子图，也不自动回退已批准计划。历史失败运行不自动改写或重启。

## 验收

- 单文件违规：首次检查点给出问题和文件；第二次模型只返回该文件；合并后构建成功，其他文件内容保持一致。
- 无法定位或局部响应多带文件：反馈为 `full`，随后完整重生；无效候选没有工作区写入。
- 源码校验与构建失败交错：共享修复计数；连续 3 次或累计第 5 次同错提前停；60 轮和硬预算不被绕过。
- 服务重启：候选引用、反馈和轮次恢复；人工确认后的下一次候选键不复用失败输出，旧版本保持可用。
- 页面和独立异常后台区分“源码校验未通过”与“构建未通过”，只展示受控原因和 Trace ID，不暴露模型源码或原始响应。
