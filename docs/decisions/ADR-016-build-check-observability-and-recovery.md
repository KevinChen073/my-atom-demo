# ADR-016：构建检查打点与模型输出失败后的显式恢复

- 状态：Accepted（2026-11-01 用户要求收集构建检查重试并纳入独立异常中心，优先处理 Trace `93358163-746c-4ebd-9b63-cdc39c4499bf`）
- 关联：[PRD](../PRD.md)、[架构](../ARCHITECTURE.md)、[异常中心](../EXCEPTION-OBSERVABILITY.md)、[ADR-013](ADR-013-source-validation-targeted-repair.md)。

## 已确认的现象与决定

该 Trace 在扩充 Token 后继续执行，源码校验失败 6 次、构建检查失败 3 次；最终 CodeLoop 两次收到 `finish_reason=stop` 的模型响应，但 JSON 解析失败，run 终态为 `model_output_invalid`。最后的已保留构建候选是 `App.tsx` 与未修改 hook/组件的类型接口不一致。原局部修复输入只有编译反馈，没有这些保持不变文件的接口上下文。

局部重生时，在修复反馈中附加**当前候选直接导入的、保持不变的 TypeScript 文件**作为只读兼容性参考，限制总字符数；输出范围仍仅为目标文件，完整候选仍须重新校验和构建。模型响应结构失败只记录固定原因码与轮次，不保存响应文本。若失败发生在 CodeLoop，且上一个构建候选、已批准计划、可修复诊断及 LangGraph `code_loop` 检查点均存在，项目拥有者可以主动打开原有人工修复卡，再明确选择继续修复或给出方向；不自动消费新的模型调用。旧可用版本不变。其他模型失败保持原有终止规则。

补充校准：后续人工修复在第 4 次构建得到 `TS2322`，编译器第二行明确指出 `pulseKey` 不属于 `CharacterProps`；原反馈提取只抓取带 `error TS...` 的首行，丢掉了这一关键子原因。构建诊断现在将最多两条受限的 TypeScript 续行合并到对应错误反馈中。第 5 次构建通过并保存版本；构建通过只说明类型与打包检查通过，浏览器交互仍需单独验证。

每次 `BuildTest` 保存独立 `build_check_attempts` 记录：run/轮次、成败、受控错误类别、固定命令、退出码、耗时、自动修复轮次、当时模型调用与 Token 用量、错误指纹、可定位目标文件、TypeScript 错误码和停机码。失败检查在 `exception_records` 中产生 `build_check_failed` 警示行；自动修复成功后保留历史警示，终态失败仍单独记录。按 `(run_id, attempt)` 幂等。独立异常后台只读这些专用安全列，在同一 Trace 详情展示最多 60 次检查；不读取原始事件 payload 或构建日志。旧记录只从既存受控事件字段回填轮次、命令、耗时、指纹和停机码；当时模型/Token 用量与目标文件缺失时显示“历史未记录”，不推断。

此决定修订[异常中心实施契约](../EXCEPTION-OBSERVABILITY.md)原“自动修复成功的中间错误不写异常表”规则，保留运维服务独立部署和敏感数据禁入边界。

## 验收

- 该 Trace 在异常中心可看到 3 次历史失败构建及最终模型输出异常；历史缺失字段有明确标识。
- 对已失败 run，拥有者能打开人工修复卡；未确认前不调用模型、不新增版本。
- 新失败构建按轮次仅写一次警示与打点；成功构建也留下检查指标，不新增警示。非拥有者不能恢复 run。
- 指纹、错误码和路径受白名单约束；模型原文、源码、请求、密钥和完整构建日志不出现在异常中心。
