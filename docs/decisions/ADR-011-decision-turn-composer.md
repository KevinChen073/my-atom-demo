# ADR-011：当前决策与发送入口同处一条对话

- 状态：Accepted（用户于 2026-11-01 以界面示意图明确指定）
- 关联：[PRD](../PRD.md)、[MVP1 UI](../MVP1-UI.md)、[ADR-010](ADR-010-structured-card-single-send.md)、[设计入口](../../design/design.md)、[单一发送 TC](../../tests/cases/SINGLE-SEND.md)。

## 决定

澄清、计划和构建失败等待态采用同一条 Agent 对话：简短说明、当前结构化卡、紧接卡片的消息输入区。卡片提供问题、建议选项或可展开的证据，输入区只有一个“发送”动作；卡片选择和自由文本仍合并为一条消息提交。等待态不再另设远离卡片的固定输入区，也不提供“前往输入区”导航。非等待态继续使用独立输入区，以便写下一轮需求草稿。

计划在主对话中默认只显示标题与少量功能重点；完整计划、数据和验收边界按需展开，并继续保留在右侧项目文档。计划卡的“按这版计划开始生成”是选择/填入消息，不直接提交或批准；仍须通过唯一的发送动作和 [ADR-010](ADR-010-structured-card-single-send.md) 的服务端明确批准门禁。

输入区只显示 `当前字数/上限`，例如 `2/2000`，不显示“关联当前计划卡”等内部提示。Enter 发送，Shift+Enter 换行；中文输入法组合输入期间的 Enter 不触发发送。按钮和键盘共用同一提交函数与禁用条件，避免重复提交。

## 对既有决策的修订

用户直接提供的目标图和键盘规则按 [ADR-002](ADR-002-change-control.md) 视为确认。本 ADR 仅替代 [ADR-010](ADR-010-structured-card-single-send.md) 及其引用文档中“等待态输入区固定在整个对话底部、与当前卡分离”的**位置与呈现**约定；单一发送、消息持久化、阶段门禁、幂等和修复白名单保持有效。讨论稿保留为历史过程记录。
