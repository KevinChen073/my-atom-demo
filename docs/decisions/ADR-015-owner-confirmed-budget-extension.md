# ADR-015：额度暂停与用户明确扩额

- 状态：Accepted（用户于 2026-11-01 明确要求）
- 关联：[PRD](../PRD.md)、[架构](../ARCHITECTURE.md)、[ADR-002](ADR-002-change-control.md)、[ADR-007](ADR-007-active-execution-budget.md)、[ADR-008](ADR-008-manual-build-recovery.md)、[ADR-009](ADR-009-build-repair-harness.md)

## 决定

新 run 的模型 Token 总预算由 40,000 调整为 **100,000**，创建 run 时连同模型调用次数、Agent 累计执行秒数、自动源码修复轮次一起持久化为该 run 的上限。旧 run 缺少上限字段时按原默认值解释（80 次、40,000 Token、900 秒、60 轮），不因服务升级自动获得额外额度。

任一硬预算耗尽时，当前 run 进入 `awaiting_budget`，暂停执行计时并展示具体触发原因、已用量及四项可选扩额。每次明确确认可增加：模型调用 **40 次**、Token **100,000**、Agent 执行 **900 秒**、自动源码修复 **30 轮**；可同时选择多项，但必须包含当前耗尽的项。扩额只增加上限，不清零已用量、不回退已批准计划，不自动批准后续决策。用户等待期间不计入 Agent 执行时间。每次扩额都需项目拥有者再次确认，没有自动续额。

确认动作使用当前卡 `card_id/spec_version` 与幂等键，在一笔数据库事务中写入决定、四项新上限和事件，然后从原 LangGraph 检查点继续。旧 `budget_exceeded` run 仅在仍为项目最近一轮且检查点可继续时，可由拥有者主动打开扩额卡；读取页面或服务重启不触发恢复。取消后不能再扩额。扩额不增加可用版本，旧版保持可用。

若自动源码修复已经以 `repair_limit` 停在人工处理卡，卡中另提供“增加 30 轮自动修复并继续”的选用项；用户仍需用同一对话输入区明确发送。决定事务先持久增加该 run 的修复轮次上限，再从 `WaitRepair` 检查点回到 `CodeLoop` 自动修复。连续 3 次同组错误或同错累计第 5 次的提前停机条件不会因增加轮次而清空。

预算暂停会写入独立异常后台的受控原因；同一 run 可能多次暂停，最终也可能发生另一种错误，因此异常记录允许多条预算记录，同时保留非预算终态记录的去重约束。不得在异常记录中保存模型响应、需求、密钥或堆栈。

## 对旧决定的修订

[ADR-007](ADR-007-active-execution-budget.md) 的“超限进入终态”、[ADR-008](ADR-008-manual-build-recovery.md) 的“预算耗尽不可人工恢复”和 [ADR-009](ADR-009-build-repair-harness.md) 的“Token 默认 40,000”由本 ADR 覆盖。15 分钟只累计 Agent 执行时间、自动修复无进展/循环提前停机及安全边界继续有效。自动修复轮次扩额不绕过连续 3 次同错或累计第 5 次同错的提前停止条件。
