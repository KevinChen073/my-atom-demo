# ADR-007：任务时长预算只计算 Agent 执行时间

2026-11-01 修订：预算超限后的终态规定已由 [ADR-015](ADR-015-owner-confirmed-budget-extension.md) 改为等待用户明确扩额；本页的执行时间累计与暂停计时语义继续有效。

- 状态：Accepted（2026-11-01 用户明确确认）
- 关联：[PRD](../PRD.md)、[架构](../ARCHITECTURE.md)、[异常后台](../EXCEPTION-OBSERVABILITY.md)、[ADR-002](ADR-002-change-control.md)

## 决定

单 run 默认 15 分钟时长上限，计算该 run 各段 **Agent 实际执行时间的累计值**。排队、等待用户回答澄清卡、等待用户确认或修改计划、进程停机期间均不计入；用户继续操作后从已累计用量继续，不重置 15 分钟。模型调用、受限工具、构建与预览检查均属于执行时间。

服务端在工作线程开始处理时开启计时，等待节点返回或任务终态时停止并持久化累计秒数。执行中定期持久化心跳；进程异常重启时清除上次未完成的计时起点，从最后一次心跳的累计值恢复，不把停机时间当成执行时间。模型请求和构建命令受剩余执行时间约束；入库可用版本前再次检查预算。超过上限进入明确的 `budget_exceeded` 终态，保留旧可用版本。

已有历史 run 没有记录执行时间，不能由创建时间与异常时间反推出实际执行秒数；旧异常继续展示任务存续时间并标注“含等待”，执行时间显示“未记录”。新异常用受控字段保存执行累计值和上限。

## 理由与迁移

旧实现用 `now - runs.created_at` 判断时长，用户隔夜确认澄清时会立即超限，与“单次执行任务 15 分钟”的含义冲突。`runs.active_seconds` 对旧记录保持 `NULL`、新 run 从零开始；`runs.execution_started_at` 仅表示当前工作段。既有模型调用次数与 Token 上限保持不变，重复确认和重启恢复仍遵循原有幂等规则。
