# ADR-009：构建修复循环的停机判定

## 决定

当前仅服务一次简单需求的主线程。`BuildTest → Diagnose → CodeLoop` 对**源码编译或类型错误**最多自动执行 60 轮修复；初次生成后的构建不占修复轮次。每次修复生成受限文件集合，重新构建，失败才重新判断。构建成功进入候选产物和预览检查；不回退计划。

每次失败从构建诊断提取具体错误，去掉行列号、ANSI 控制符和空白差异，保留命令、错误代码、文件与错误文字，哈希为稳定指纹。同次构建的一组指纹去重后写入 LangGraph state，事件只记录指纹，不复制完整源码或密钥。判断顺序：

1. 最近 **3 次失败构建的完整错误指纹集合相同**，视为无进展，停止自动修复。
2. 任一具体错误指纹在失败构建中**累计第 5 次出现**，即使中间穿插其他错误，也视为问题循环，停止自动修复。
3. 已执行 **60 轮自动修复**且构建仍失败，停止自动修复。

到达上述条件转 `NeedsUser → WaitRepair`，展示停机原因、失败命令、最近错误、累计构建次数、最近 5 次构建及日志引用。用户仍可在同一 run 内主动选择继续修一次、指定修复方向或原样重建；每次人工动作只做一轮，失败后再等待用户，不重新进入自动循环。环境、依赖安装或未知故障直接交人工，不能自动改源码。失败候选不入可用版本。

独立管理员异常后台对三种停机分别记录 `build_no_progress`、`build_recurring_error`、`build_repair_limit` 及固定中文原因；具体源码/日志仍只允许项目拥有者在构建日志中查看。

模型调用默认上限调整为 80，以免固定的调用次数先于 60 轮结构性上限；token 默认 40,000、累计 Agent 执行时间默认 900 秒不变。任一硬预算耗尽、取消或安全限制可更早结束；因此 60 轮是**最高允许次数，不承诺实际一定执行满 60 轮**。旧 run 的历史日志不补算指纹，新规则自其下次构建起累计。

2026-11-01 用户再次明确调整：自动修复循环由 30 轮改为 60 轮；同一错误累计停机点由第 4 次改为第 5 次。连续 3 次相同错误集合的无进展停机条件不变。

本决定修订 [ADR-008](ADR-008-manual-build-recovery.md) 中以“两轮自动修复耗尽”为背景的旧阈值，保留其人工恢复合同。
