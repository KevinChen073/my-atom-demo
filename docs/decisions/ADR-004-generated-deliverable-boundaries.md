# ADR-004：生成交付物的持久化、运行与可用版本回滚边界

- 状态：Accepted（用户于 2026-10-31 明确确认）；本次仅修订文档，代码尚未按此迁移。
- 关联：[PRD](../PRD.md#5-持久化与版本)、[系统架构](../ARCHITECTURE.md)、[变更守则 ADR-002](ADR-002-change-control.md)。
- 覆盖范围：替代 PRD 与架构中关于**生成应用业务数据使用服务端 CRUD/SQLite** 的旧目标；不改变 MYATOM 平台项目、会话、checkpoint、事件、异常后台使用服务端持久化的决定。保留 [ADR-001](ADR-001-baseline.md) 作为历史基线。

## 背景

当前 MVP2 实现用预览服务的 `AppDataService` 和独立 SQLite 保存生成应用业务记录。用户将“可用回滚”收敛为已呈现代码版本的完整快照与指针切换，并把生成交付物限定为浏览器业务持久化，从而暂不处理数据库、缓存与业务数据迁移/回滚。此决定已由用户直接确认，符合 ADR-002 的变更流程。

## 决定

1. **对象区分**：MYATOM 平台仍在服务端持久保存项目、运行、决策、事件、交付物版本和当前版本指针；以下限制针对 MYATOM **生成的交付物**，不限制平台 API、预览网关、独立异常后台的部署端口或平台数据库。
2. **生成范围**：交付物采用固定 React + TypeScript + Vite Web 模板。业务数据只允许保存在该生成应用预览 origin 下的浏览器 `localStorage`；不提供 SQL 数据库、服务端业务 CRUD、缓存或远程业务存储。若交付物需要后端，最多一个后端进程、一个监听端口，且后端不持久化业务数据；纯前端交付物可没有后端。计划卡、生成提示和校验规则要拒绝越界方案。
3. **本地数据语义**：同一浏览器、同一项目的稳定 origin 刷新或重开应用应读回数据；不同项目必须隔离 origin，存储键名前缀不构成权限边界。清除浏览器存储、使用另一浏览器/设备或改变预览 origin 后不保证恢复或同步；不得把凭证、密钥或敏感用户数据放进 `localStorage`。这些限制须向使用者说明。
4. **可用版本**：每个呈现给用户作为“可用版本”的交付物，必须有完整持久化的不可变源码、资源、依赖锁/模板标识、构建产物、manifest、测试结果引用，并通过构建及预览可用性检查。失败候选保留诊断即可，不计入可用版本，不影响当前版本。每项目最多保留 **5** 个可查看、可预览、可回滚的可用快照；第 6 个成功版本入库并切为当前版本后，淘汰最早且非当前的快照。保存、切换和清理须可恢复，不能留下指向已删除文件的版本。
5. **回滚动作**：项目服务端持久保存 `active_version_id`。用户在版本列表临时查看旧版只改变预览选择；明确执行“设为当前版本”时，校验项目权限与版本可用性，只把当前版本指针原子切换到该快照。不依赖 Git、不重新调用模型、不创建新快照。刷新或重新进入仍打开该版。用户以后再次迭代并成功构建，才产生新版本。列表须标明当前版本，并在达到上限时告知新成功版本将淘汰最早快照。
6. **业务数据不回滚**：浏览器 `localStorage` 数据不属于交付物快照，选择旧版或回滚均不自动改写。此处“可用回滚”保证代码与构建产物能恢复和打开，**不保证**旧代码与浏览器现存数据结构兼容。若观察到不兼容，界面应明确提示；数据库、缓存、跨版本数据迁移和业务数据回滚作为独立命题，当前不承诺。

## 示例与验收影响

- 番茄钟待办：任务和计时状态按产品需要写入 `localStorage`，同浏览器/同 origin 刷新读回。
- 点老头游戏：皮肤、得分等需持久化的状态遵守相同规则。
- 移动点单：交付“小程序风格移动 H5”；购物车/订单是本浏览器数据，不宣称跨用户订单同步、可信服务端价格、支付或真实商家接单。即使使用可选单端口后端，业务记录仍只在浏览器存储。
- 版本验收：至少覆盖成功版本 1–6 的保留上限、失败不影响当前、旧版回滚后刷新仍生效、回滚不改浏览器业务数据、同项目稳定 origin 刷新读回，以及另一项目的预览代码不能读取该存储。旧版与新数据结构不兼容时记录限制，不以“数据也回滚”作为验收标准。

## 与当前实现的差距

本 ADR 是**目标设计，不是完成声明**。现有 [MVP2 实施记录](../MVP2-IMPLEMENTATION.md)描述生成应用经 `AppDataService` 写入 `data/app_data.sqlite3`；当前预览共用 `127.0.0.1:8001` origin，不能以 `localStorage` 键名前缀替代项目隔离；现有版本选择能回看旧产物，但尚无本 ADR 要求的持久 `active_version_id`、最多 5 版的淘汰策略与完整回滚操作。历史实施和测试证据保留原事实；后续实现与 TC 更新须按本 ADR 校准，并重新实测后才可宣称满足新边界。
