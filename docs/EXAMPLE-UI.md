# MYATOM 首页示例入口（v0.1）

状态：2026-10-31，实施设计。范围遵循 [PRD](PRD.md)、[架构](ARCHITECTURE.md)和已确认的[桌面工作台视觉方向](WORKBENCH-V2.md)；变更冲突按 [ADR-002](decisions/ADR-002-change-control.md)处理。示例内容唯一来源是 [`examples/catalog.json`](../examples/catalog.json)。

生成示例的业务持久化与后端限制以 [ADR-004](decisions/ADR-004-generated-deliverable-boundaries.md) 为准；当前示例目录和自动测试已按旧项目预览域 `localStorage` 更新。共享 origin 与项目 ID 键前缀是 [ADR-026](decisions/ADR-026-shared-origin-project-storage.md) 的新目标，尚未迁移示例生成链路。真实模型输出及浏览器内业务流程仍需逐例验收。

## 目标与布局

首页保留“自然语言需求 → 需求澄清 → 计划确认”的主路径。左侧是可编辑的项目名称与需求表单，右侧展示目录中的番茄钟 Todo、带皮肤的点击游戏和移动点单三个示例。示例是启动草稿，不是已经生成的应用或可直接打开的演示。首页使用现有暖中性、墨绿与陶土橙视觉 token；在 1440×900、1366×768、1280×720 桌面视口检查可读性和滚动。

右侧示例从目录读取 `title`、`subtitle`、`description`、`tags`，不在前端复制 `request_text`，也不展示用于测试的 `smoke` 字段。移动点单明确写为“小程序风格的移动 H5”，符合当前固定 Web 模板；原生微信小程序仍未纳入生成能力。若最终要求超出固定 React+TS+Vite Web 模板，按变更守则确认后再调整。

## 交互

1. 每个示例是完整可聚焦的按钮；Tab 进入，Enter/Space 选用。点击只把目录中的 `title` 与 `request_text` 填进表单草稿，并把焦点送到需求文本框，方便继续修改。不会自动创建项目、调用模型或消耗额度。
2. 选中的卡片显示“已填入需求”，表单旁以 `aria-live="polite"` 告知“已填入，可修改后开始梳理需求”。用户编辑项目名称或需求后，取消示例选中态；保留用户修改内容。
3. 只有点击“开始梳理需求”才沿用现有表单校验与幂等提交。空需求、网络失败、重复提交等反馈遵循已有流程。示例卡片选中态不能被误读为构建成功或计划已确认。
4. 示例内容受目录版本管理；前端只负责选择与展示，不根据 `smoke` 或标题在浏览器中推断特殊生成策略。

## 验收

- 三个示例均在桌面首页可发现；键盘可依次选中，焦点可见，选中反馈可被屏幕阅读器听到。
- 每项填入的标题、需求与目录逐字一致；选中后仍需人工提交，表单编辑可用。
- 选中 A 再选 B 时只保留 B 的标题与需求；手动修改后选中态撤销；尚未提交时服务端项目数不增加。
- 1280×720、1366×768、1440×900 无水平溢出；必要时首页可垂直滚动，不遮挡提交按钮。
- 目录测试字段 `smoke` 不出现在 UI 或无关浏览器文本中；移动点单不宣称原生微信能力。

测试记录由 [TC 清单](../tests/cases/)维护；本页描述界面契约，不代替真实浏览器走查。
